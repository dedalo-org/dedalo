Turn code merges into sustainable open-source funding.

Dedalo reads merge history straight from your repository, scores who contributed what, and distributes a funding round to contributor wallets — taking a protocol fee that flows to the network's Open Collective, so the network funds itself instead of depending on grants.

Four stages, one boundary that matters

Everything that decides who gets what happens offline and deterministically. Only the last stage touches the outside world.

01 · git

Read the merges

Merge commits on your branch, the commits each one introduced, and its diff against the mainline. No separate database of contributions.

02 · attribution

Score the work

Integer weights from rules you declare: a flat score per merged PR, per-line scoring, a cap so one vendored dependency cannot drain a round, and Co-authored-by: splitting.

03 · payout

Build the plan

Fees off the top, the rest split by weight, contributors resolved to wallets. The result is content-addressed — reviewable in a pull request.

04 · settlement

Execute it

A backend re-verifies the plan and broadcasts it. Nothing moves unless you ask for it explicitly.

Stages 1–3 are pure. The same repository and the same dedalo.toml always produce the same plan id, on any machine — so a plan whose id changed is a plan someone tampered with.

Every round is cut in a fixed order, and the numbers are yours to set.

What the code guarantees

These are the reasons a payout can be trusted. Each one is enforced by tests.

No floating point in money

Every amount is an integer count of base units. Percentages are basis points. Nothing rounds by accident.

Splits conserve the total

Largest-remainder distribution: a round always sums back to exactly what you funded. No dust created, none stranded.

Fees round down

Rounding remainders land in the contributor pool, never in the protocol's pocket.

One wallet, one transfer

A contributor with several git emails is paid once, so a batch cannot double-send.

Nobody is silently dropped

Someone who earned a share but has no wallet on file is reported in the plan, not quietly removed.

Rounds are idempotent

The ledger refuses to settle the same plan twice, so a retried CI job cannot pay twice.

Install

Every archive ships a SHA-256 checksum, and the installer refuses to run without verifying it.

script 
curl -fsSL https://raw.githubusercontent.com/\
4137314/dedalo/main/install.sh | sh
cargo 
cargo install dedalo --locked
# or, without compiling:
cargo binstall dedalo
nix 
nix run github:4137314/dedalo -- status
container 
docker run --rm -v "$PWD:/repo" \
  ghcr.io/4137314/dedalo plan --amount 1000

Or run it in CI

Dedalo ships as a GitHub Action, because a payout belongs in the pipeline that merged the code.

.github/workflows/payouts.yml 
- uses: actions/checkout@v5
  with:
    fetch-depth: 0        # attribution needs the full history

- uses: 4137314/dedalo@v0
  with:
    command: plan
    amount: "1000"

Project status

On-chain broadcasting is not live yet.

The pipeline from git history to a verified, reproducible payout plan is implemented and tested end to end. The evm backend validates its configuration, re-verifies the plan and builds the exact distributor call — then stops before signing.

Shipping an unaudited signing path would put real funds at risk. Until the distributor contract is deployed and audited, use the default dry-run backend: identical numbers, minus the broadcast.

  • Git-derived attribution with co-author support
  • Deterministic, content-addressed payout plans
  • Fee schedule with protocol / treasury / contributor split
  • Append-only ledger with idempotent rounds
  • GitHub Action, container image, signed-checksum releases
  • Audited distributor contract and EVM broadcasting
  • Review-weighted attribution — reviewers earn too
